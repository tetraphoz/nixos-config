* NixOS Flake + Doom Emacs Dotfiles

This repository contains my NixOS flake, host configuration, home configuration, and dotfiles.  
It’s set up for a desktop-focused workflow using *Doom Emacs*, *XMonad*, and a collection of terminal and X11 app configs.

** Overview

- *NixOS system config* under =hosts/=
- *Home Manager config* under =home/=
- *Dotfiles* under =dotfiles/=
- *Doom Emacs config* in =dotfiles/doom.d/=

*** Fingerprint Authentication
The ThinkPad P52 exposes a Synaptics Metallica MIS reader with USB ID
=06cb:009a=. This is a Validity protocol device and is *not* supported by the
normal =libfprint= Synaptics driver. The NixOS configuration therefore uses
the same stack as the linked P52 guide: =open-fprintd= plus the
=python-validity= backend, with the =fprintd= clients and PAM module.

After switching to the configuration, check that the backend is running and
enroll a fingerprint as the user who will authenticate:

#+begin_src bash
systemctl status open-fprintd python3-validity
fprintd-enroll
fprintd-list "$USER"
fprintd-verify
#+end_src

The first initialization may need to upload firmware to the sensor. If the
backend reports that the sensor is in a bad state, stop it and run the
firmware/reset tools as root before starting it again:

#+begin_src bash
sudo systemctl stop python3-validity
sudo validity-sensors-firmware
sudo python3 /run/current-system/sw/share/python-validity/playground/factory-reset.py
sudo systemctl start python3-validity
#+end_src

For troubleshooting, inspect both backend and kernel USB logs:

#+begin_src bash
journalctl -u open-fprintd -u python3-validity -b
journalctl -k -b | grep -iE 'usb|fprint|validity|synaptics'
#+end_src

Suspend/resume units are enabled by the NixOS module. A password remains
available as the fallback authentication method. The fingerprint database is
managed by the backend; do not copy it between machines.

** System Structure

*** =flake.nix=
Defines the NixOS flake inputs and outputs.

*** =hosts/p52=
Host-specific NixOS configuration for the machine =p52=.

*** =home/tetra.nix=
Home Manager configuration for the user =tetra=.

*** =dotfiles/=
Contains application configs that are symlinked or managed through the flake/home setup.

** Usage

*** Build / switch the system
#+begin_src bash
sudo nixos-rebuild switch --flake .#p52
#+end_src

*** Build Home Manager config
The normal path is the NixOS-integrated Home Manager module, so the system
command above applies both configurations together. For a standalone Home
Manager deployment, the flake also exposes the
=homeConfigurations.tetra= output:
#+begin_src bash
home-manager switch --flake .#tetra
#+end_src

*** Remote desktop and private networking
Sunshine is enabled as a Moonlight host for the active X11 session. Its
streaming and web UI ports are opened by the NixOS module. After switching,
open the Sunshine web UI from a trusted network to create credentials, then
pair a Moonlight client with this machine's hostname or Tailscale address.

Tailscale is enabled as well, but this configuration deliberately does not
store an auth key. Authenticate the machine once after the first switch:
#+begin_src bash
sudo tailscale up
sudo tailscale status
#+end_src

The Tailscale address can then be used to reach Sunshine without exposing the
host's streaming ports to the public Internet.

*** Validate the configuration
#+begin_src bash
nix flake check
nix build .#nixosConfigurations.p52.config.system.build.toplevel --dry-run
#+end_src

*** Update flake inputs
#+begin_src bash
nix flake update
#+end_src
